Why This Project Exists

This project complements the NZ ventilation case study. The ventilation project targets HVAC, building services and commissioning. This project targets product engineering: enclosure design, DFM, test fixtures, electronics packaging, firmware boundaries and reliability validation.

  • SolidWorks CAD V2 includes detailed lower enclosure, upper lid, gasket, PCB placeholder, battery placeholder and exploded assembly.
  • The model now makes the sealing path, fastening path, strap-mount path and service-access path visible.
  • Proteus architecture notes now map MCU, sensor, power, debug and radio-boundary signals.
  • Keil / embedded C now includes a state machine, pin map and ARMCLANG-verifiable source structure.
  • Abaqus is used for a completed concept strap-mount pull load case, with corner-load FEA planned next.

Evidence Boundary

This page currently shows planning documents and SolidWorks concept CAD V1/V2. It does not claim an IP rating, physical test data, production readiness, final PCB design or validated firmware. Those evidence items will be added only after the corresponding work is completed.

Abaqus Strap-Mount FEA

A concept Abaqus 2025 load case was added for the rear strap-mount lugs. The simplified model applies a 150 N total strap pull, split across the two lug holes, using a PC-ABS concept material and C3D10 solid mesh.

150 NTotal strap pull load
1.57 MPaMaximum von Mises stress
0.010 mmMaximum displacement
25.47Concept yield ratio

This is early concept FEA: the geometry, support boundary and material values are simplified. It is useful design evidence for load-path thinking, not a certified safety factor or physical validation result.

Electronics + Firmware Architecture

The project now links the mechanical enclosure to a Proteus-style electronics architecture and Keil/uVision firmware package. The current evidence focuses on signal ownership, state-machine behaviour, battery/sensor fault handling and the service/debug interface.

Electronics Evidence

  • Proteus architecture note for MCU, I2C sensor, battery monitor, regulator, LEDs, SWD service header and UART radio boundary.
  • Concept signal table linking each electrical signal to firmware ownership and validation intent.
  • Mechanical links to PCB envelope, battery restraint, sealed service/debug port and sensor membrane opening.

Firmware Evidence

  • Keil/uVision project scaffold using the local uVision launcher.
  • ARMCLANG-verifiable embedded C source structure with state machine, mock sensor driver and power monitor.
  • Pin map and firmware architecture note covering sleep, sampling, filtering, transmit, low-battery, fault and service states.
